# Справочник по конфигурации проекта

Файлы в этой папке — обычный JSON. В него нельзя добавлять комментарии `//` или
`/* ... */`: такие вставки сломают чтение конфигурации через `JSON.parse`.
Поэтому назначение и варианты значений всех ключей описаны здесь.

Общие правила:

- пути задаются относительно корня AI workspace или клиентского репозитория —
  конкретная база указана в описании ключа;
- в путях используются `/`, в том числе при настройке на Windows;
- элементы списков `deny`, `allow` и `humanGates` — стабильные машинные
  идентификаторы в `snake_case`;
- пустой список `[]` означает «нет элементов», а пустая строка `""` —
  «использовать значение среды/корпоративное значение по умолчанию» только там,
  где это явно указано;
- ослабление ограничений безопасности, данных или human gates требует отдельного
  согласования. Сам факт существования варианта значения не означает, что его
  можно выбрать для этого проекта.

## `profile.json`

Основной профиль проекта: где находится клиентский репозиторий, какие данные и
инструменты разрешены, какими командами проект проверяется и где нужен человек.

| JSON-путь | Тип и варианты | За что отвечает |
|---|---|---|
| `schemaVersion` | Целое число. Сейчас поддерживается только `1`. | Версия формата файла. Это не версия SDK или AI workspace. Не увеличивать без миграции потребителей конфигурации. |
| `project` | Объект. | Группирует идентификацию проекта. Самостоятельно не настраивается. |
| `project.id` | Непустая строка, обычно `snake_case`; без персональных данных. | Стабильный машинный ID проекта, попадает в контекст агента. Менять после начала работы нежелательно. |
| `project.displayName` | Непустая строка. | Человекочитаемое внутреннее название, которое показывается в контексте и отчётах. |
| `targetRepository` | Объект. | Группирует расположение и Git-идентификацию клиентского репозитория. |
| `targetRepository.localRelativePath` | Относительный путь, например `../sdk-ios`. | Путь от корня AI workspace до checkout клиентского проекта. Репозитории должны быть соседними, а не вложенными друг в друга. |
| `targetRepository.runtimeRelativePath` | Относительный путь, например `../.ai-runtime`. | Путь от корня AI workspace до временного runtime-каталога агента. Он должен находиться вне клиентского репозитория и AI workspace. |
| `targetRepository.allowedRemotes` | Массив точных SSH/HTTPS Git URL. | Белый список допустимых `origin` клиентского репозитория. Wildcard не поддерживается; различные URL одного репозитория можно перечислить отдельно. Пустой список делает проверку workspace неуспешной. |
| `targetRepository.defaultBranch` | Имя существующей ветки, обычно `main`, `master` или `develop`. | Базовая ветка для вычисления diff и проверки артефактов. Это не команда переключения ветки. |
| `dataPolicy` | Объект. | Группирует правила о данных, которые можно передавать агенту и сохранять в артефактах. |
| `dataPolicy.lane` | `"green"`, `"amber"` или `"red"`. | Договорно утверждённый режим работы с данными: `green` — разрешён утверждённый проектный контекст; `amber` — нужны дополнительные ограничения/проверка; `red` — данные нельзя передавать агенту без отдельного разрешения. Точные границы определяются договором, а не этим файлом. |
| `dataPolicy.allowSourceCode` | Boolean: `true` / `false`. | Можно ли агенту читать исходный код клиентского проекта. `false` запрещает использовать код как входной контекст. |
| `dataPolicy.allowTestData` | Строка-политика. Для этого workspace допустимо `"synthetic_only"`; более широкое значение требует отдельного решения владельца данных. | Определяет, какие тестовые данные можно использовать. `synthetic_only` означает только искусственно созданные данные без production- или personal data. |
| `dataPolicy.deny` | Массив идентификаторов категорий данных. | Категории, которые нельзя читать, копировать в контекст или сохранять. Список расширяемый; удаление элемента ослабляет политику. Текущие значения запрещают секреты, production data, personal data и проектные credentials. |
| `ai` | Объект. | Группирует выбор AI-инструмента и его доступ к внешним возможностям. |
| `ai.defaultTool` | `"codex"` или `"claude"`. | Инструмент, который команда `aiw` использует, если `--tool` не передан явно. |
| `ai.codex` | Объект. | Настройки Codex. |
| `ai.codex.model` | Строка: `""` или точный ID явно утверждённой модели. | Пустая строка оставляет корпоративную модель по умолчанию; непустая фиксирует модель для Codex. Не угадывать ID модели. |
| `ai.claude` | Объект. | Настройки Claude. |
| `ai.claude.model` | Строка: `""` или точный ID явно утверждённой модели. | Пустая строка оставляет корпоративную модель по умолчанию; непустая фиксирует модель для Claude. Не угадывать ID модели. |
| `ai.cloudAgent` | Boolean: `true` / `false`. | Разрешён ли облачный режим агента. `false` оставляет выполнение локальным; `true` допустим только после проверки политики данных и среды. |
| `ai.networkForGeneratedCommands` | Boolean: `true` / `false`. | Разрешён ли сетевой доступ командам, которые предлагает или запускает агент. `false` — безопасное значение по умолчанию; `true` не отменяет approvals и прочие сетевые ограничения среды. |
| `ai.mcpAllowlist` | Массив строковых ID MCP-серверов; `[]` запрещает все явно не предоставленные серверы. | Белый список MCP-интеграций, которым можно передавать проектный контекст. Добавлять только проверенные точные ID. |
| `commandPolicy` | Объект. | Группирует абсолютные запреты на команды. |
| `commandPolicy.forbiddenExecutables` | Массив имён executable без аргументов и wildcard. | Команды, которые агент не должен запускать ни напрямую, ни через wrapper. Для этого проекта список обязан содержать `fastlane`. |
| `commandPolicy.rule` | Непустая строка с нормативным правилом. | Человекочитаемое объяснение масштаба запрета, которое попадает в контекст агента. Не заменяет машинный список executable, а уточняет обходные варианты и исключения. |
| `projectCommands` | Объект `имя -> строка команды/маркер`. | Единый источник разрешённых проектных команд. Стандартные ключи перечислены ниже; дополнительные команды добавляются только при наличии потребителя/документации. |
| `projectCommands.install` | Команда либо маркер `MANUAL_ONLY`. | Как подготавливаются зависимости. `MANUAL_ONLY: <инструкция>` означает, что действие выполняет человек по указанной процедуре. До выяснения команды может временно использоваться `UNRESOLVED`, но не перед реализацией. |
| `projectCommands.format` | Команда, `UNRESOLVED` или `FORBIDDEN`. | Проверка/применение форматирования. В текущем профиле команда запускает `swift-format` в режиме lint, то есть проверяет файлы без перезаписи. |
| `projectCommands.lint` | Команда, `UNRESOLVED` или `FORBIDDEN`. | Статический lint проекта. Ненулевой exit code означает провал проверки. |
| `projectCommands.typecheck` | Команда, `UNRESOLVED` или `FORBIDDEN`. | Компиляционная проверка типов/сборка без запуска тестов. Текущая команда собирает SDK для generic iOS Simulator без code signing. |
| `projectCommands.testTargeted` | Команда, `UNRESOLVED` или `FORBIDDEN`. | Наименьший одобренный запуск релевантных тестов. Конкретный test target/case можно уточнять средствами используемого test runner, не подменяя команду запрещённым инструментом. |
| `projectCommands.testFull` | Команда, `UNRESOLVED` или `FORBIDDEN`. Для этого workspace обязательно `FORBIDDEN`. | Полный тестовый прогон. `FORBIDDEN` — абсолютный запрет, а не просьба запросить approval. |
| `projectCommands.build` | Команда, `UNRESOLVED` или `FORBIDDEN`. | Одобренная сборка проекта. Текущая команда собирает Debug-конфигурацию для generic iOS Simulator без code signing. |
| `humanGates` | Массив строковых идентификаторов. | Изменения/операции, перед которыми агент обязан остановиться и получить решение человека. Список расширяемый; удаление элемента ослабляет контроль. Значения описаны ниже. |

Значения `humanGates` в текущем профиле:

| Значение | Когда срабатывает |
|---|---|
| `architecture_change` | Меняется архитектурная граница, ownership или основной паттерн взаимодействия компонентов. |
| `new_dependency` | Добавляется внешняя библиотека, package, pod или иной dependency. |
| `database_migration` | Меняется схема базы данных или требуется миграция хранимых данных. |
| `authentication_or_authorization` | Меняется аутентификация, авторизация или модель доступа. |
| `external_api_change` | Меняется контракт с внешней системой/API. |
| `public_sdk_api_change` | Меняется потребительский API, поведение или совместимость SDK. |
| `privacy_or_permission_change` | Меняется сбор данных, consent или системные permissions. |
| `persistent_model_migration` | Меняется формат/смысл долгоживущих Core Data, UserDefaults, файловых или JSON-данных. |
| `network_trust_change` | Меняются TLS, certificate pinning или иные правила сетевого доверия. |
| `minimum_platform_change` | Меняется минимальная поддерживаемая версия платформы. |
| `package_or_distribution_change` | Меняются podspec, SPM/XCFramework, versioning или публикация SDK. |
| `destructive_command` | Команда может удалить или необратимо перезаписать данные. |
| `commit`, `push`, `merge` | Соответствующая Git-операция. Каждый gate независим. |
| `deployment` | Развёртывание или публикация артефактов. |

## `permissions.json`

Описывает ожидаемые границы нативного и Docker-режимов. Файл служит политикой
workspace; фактическая среда выполнения может накладывать более строгие
ограничения и никогда не обязана расширять доступ до указанного здесь уровня.

| JSON-путь | Тип и варианты | За что отвечает |
|---|---|---|
| `policyVersion` | Целое число. Сейчас используется `1`. | Версия формата permission policy. Не связана со `schemaVersion` профиля. |
| `native` | Объект. | Политика запуска агента непосредственно на машине разработчика. |
| `native.filesystemMode` | `"read-only"` или `"workspace-write"`; более широкий режим допустим только если он явно поддержан runner и отдельно согласован. | Базовый доступ к файловой системе: только чтение либо запись внутри workspace. Текущее `workspace-write` не разрешает запись в защищённые пути. |
| `native.networkForGeneratedCommands` | Boolean: `true` / `false`. | Сетевой доступ сгенерированных команд в native-режиме. Должен согласовываться с одноимённым ключом в `profile.json`; `false` — более строгое значение. |
| `native.approvalMode` | Строка режима runner. Для этой политики используется `"on-request"`; другие значения разрешены только если документированы выбранным runner. | Когда агент запрашивает подтверждение для потенциально опасных/расширенных действий. `on-request` означает запрос по мере необходимости и не отменяет абсолютные запреты. |
| `native.protectedClientPaths` | Массив glob-путей относительно корня клиентского репозитория. | Пути, запись в которые требует отдельного решения или запрещена средой. `*` покрывает один сегмент, `**` — произвольную глубину. |
| `native.requireHumanConfirmation` | Массив строковых идентификаторов действий. | Действия, требующие явного подтверждения человека. Текущие значения: установка dependency, изменение Git config, commit, push и сетевой доступ. Можно добавлять новые категории; удаление ослабляет политику. |
| `native.deny` | Массив строковых идентификаторов действий. | Абсолютно запрещённые действия: approval не делает их разрешёнными. Текущий список запрещает Fastlane, merge, deploy, production access, IAM changes и чтение секретов из home-каталога. |
| `docker` | Объект. | Границы монтирования при запуске агента в контейнере. |
| `docker.clientMount` | `"read-only"` или `"read-write"`. | Режим mount клиентского репозитория. `read-write` нужен для реализации изменений; `read-only` подходит для анализа/ревью. |
| `docker.aiWorkspaceMount` | `"read-only"` или `"read-write"`. | Режим mount этого AI workspace. Текущее `read-only` защищает правила и конфигурацию от изменения из контейнера. |
| `docker.runtimeMountForAgent` | `"read-only"` или `"read-write"`. | Доступ агента к подготовленному runtime mount. Текущее `read-only` не позволяет модифицировать runtime-инструкции. |
| `docker.hostHomeMounted` | Boolean: `true` / `false`. | Монтируется ли домашний каталог хоста. Без отдельной необходимости должно быть `false`, чтобы не открывать пользовательские файлы и credentials. |
| `docker.dockerSocketMounted` | Boolean: `true` / `false`. | Монтируется ли Docker socket хоста. `true` фактически даёт контейнеру очень широкие права на хосте; безопасное значение по умолчанию — `false`. |

## `forbidden-artifacts.json`

Определяет, какие файлы и текст нельзя доставлять в клиентский репозиторий.
Проверка применяется к изменённым/новым файлам и добавленным строкам/commit
messages, которые видит `aiw verify`.

| JSON-путь | Тип и варианты | За что отвечает |
|---|---|---|
| `denyPaths` | Массив glob-шаблонов относительно корня клиентского репозитория. | Запрещённые пути артефактов. `*` не пересекает `/`, `**` покрывает вложенные каталоги. Для корневого и вложенного файла часто нужны два шаблона, например `AGENTS.md` и `**/AGENTS.md`. |
| `denyCommitPatterns` | Массив строк — JavaScript regular expressions, регистр игнорируется. | Запрещённые фразы в новых commit messages и добавленных строках diff. Синтаксически неверное regex-выражение останавливает проверку с ошибкой. |
| `allowPaths` | Массив glob-шаблонов; `[]` — без исключений. | Точечные исключения из `denyPaths`: совпадение с allow проверяется раньше deny. Добавлять только для документированного клиентского исключения; этот ключ не отменяет `denyCommitPatterns`. |

## `skill-improvement-policy.json`

Управляет тем, как ошибки агента могут превращаться в изменения общих skills.
Это защита от автоматического «обучения» на клиентском коде, тикетах, секретах
или единичном проектном случае.

| JSON-путь | Тип и варианты | За что отвечает |
|---|---|---|
| `schemaVersion` | Целое число. Сейчас поддерживается только `1`. | Версия формата политики улучшения skills. |
| `mode` | Для этого workspace обязательно `"human-reviewed"`. | Режим принятия улучшений: каждое изменение skill проходит человеческое ревью. Другие режимы текущая проверка workspace не принимает. |
| `requireSanitizedFailureRecord` | Boolean. Для текущей политики — `true`. | Требует обезличенную запись о сбое без клиентского кода, сырых prompts, секретов и уникальных идентификаторов. |
| `requireBehavioralEval` | Boolean. Для текущей политики — `true`. | Требует behavioral eval, который воспроизводит нежелательное поведение и проверяет ожидаемое. |
| `requireAdjacentRegression` | Boolean. Для текущей политики — `true`. | Требует соседний regression-кейс, чтобы исправление одного поведения не ухудшило близкий сценарий. |
| `minimumProjectArchetypesForUniversalSkillChange` | Целое число `>= 1`; сейчас `2`. | Минимальное число разных архетипов проектов, подтверждающих, что изменение действительно универсально, а не специфично одному проекту. |
| `allowAutonomousSkillMutation` | Boolean. Для этого workspace обязательно `false`. | Может ли агент сам изменять общие skills без human review. Текущая проверка запрещает `true`. |
| `allowAutonomousMerge` | Boolean. Для этого workspace обязательно `false`. | Может ли агент сам сливать улучшение skill. Текущая проверка запрещает `true`. |
| `learningData` | Объект. | Группирует категории данных, допустимые и запрещённые как evidence для улучшения skills. |
| `learningData.allow` | Массив идентификаторов категорий. | Разрешённые sanitized-материалы: синтетические случаи, достаточно обезличенные failure patterns и очищенные behavioral scores. Добавление категории расширяет использование данных и требует проверки. |
| `learningData.deny` | Массив идентификаторов категорий. | Материалы, которые нельзя переносить в learning/eval artifacts. Текущий список запрещает исходники проекта, скопированные тикеты, сырые prompts/transcripts, секреты, production/personal data и уникальные ID проекта. |

## Как безопасно менять конфигурацию

1. Меняйте минимальное число ключей и не удаляйте ограничения «для удобства».
2. Проверяйте синтаксис всех JSON-файлов стандартным JSON parser.
3. Запускайте `aiw doctor --tool <codex|claude> --mode <native|docker>`.
4. Для delivery-проверки используйте `aiw verify`; она проверяет hygiene, но не
   заменяет build, lint и tests.
5. Ослабление data policy, permissions, forbidden artifacts, human gates или
   skill-improvement policy согласуйте с владельцем Security/AI workspace.
